# PII redaction for session memories

This document describes how PII in a memory's `content` is redacted before the memory is stored and embedded.

## Where redaction has to happen

A remembered memory is written as a single `IndexRequest` to `.context-engine-session-memory` ([SessionMemoryIndexService.remember](src/main/java/org/elasticsearch/xpack/contextengine/memory/SessionMemoryIndexService.java#L75)).

- The stored document combines `content` and every `media` item into the `inputs` array ([SessionMemory.toXContent](src/main/java/org/elasticsearch/xpack/contextengine/memory/SessionMemory.java#L197)).
- `inputs` is a `semantic` field, so it is embedded at index time ([template](../core/template-resources/src/main/resources/context-engine-session-memory.json#L45)).
- The embedding is generated by [ShardBulkInferenceActionFilter](../inference/src/main/java/org/elasticsearch/xpack/inference/action/filter/ShardBulkInferenceActionFilter.java) on the shard bulk request, after any ingest pipeline has run ([TransportAbstractBulkAction](../../../server/src/main/java/org/elasticsearch/action/bulk/TransportAbstractBulkAction.java#L321)).

Redaction therefore has to run during ingest or before it. Only text can be redacted; Elasticsearch has nothing that redacts the contents of images or PDFs.

## Approaches

### Ingest pipeline

The plugin can either set `index.default_pipeline` in the data stream template or set a pipeline on each `IndexRequest`. Two processors can redact text:

- [`redact`](../redact/src/main/java/org/elasticsearch/xpack/redact/RedactProcessor.java) uses Grok patterns. It catches emails, phone numbers, IP addresses, and SSNs, but not names.
- [`inference`](../ml/src/main/java/org/elasticsearch/xpack/ml/inference/ingest/InferenceProcessor.java) can run a NER model, which requires an Eland import and an ML node. EIS does not serve a NER model. The processor also cannot call a `chat_completion` endpoint, because it sends its request through `InferenceAction`, which only accepts `completion` ([ElasticInferenceService](../inference/src/main/java/org/elasticsearch/xpack/inference/services/elastic/ElasticInferenceService.java#L619)).

### Inference call in `remember()`

The plugin sends the content to a `chat_completion` endpoint with a redaction prompt and indexes the reply. Because the plugin receives the redacted text, the remember response contains it as well.

## The POC

The POC uses the inference call in `remember()`, which requires EIS.

- `xpack.context_engine.session_memory.redaction.enabled` defaults to `true`, and `xpack.context_engine.session_memory.redaction_inference_id` defaults to `.rainbow-sprinkles-elastic` ([ContextEnginePlugin](src/main/java/org/elasticsearch/xpack/contextengine/ContextEnginePlugin.java)). Setting the id to another `chat_completion` endpoint overrides the default; an empty id is not possible, because Elasticsearch drops empty setting values, so redaction is turned off with the `enabled` flag.
- When a memory has `content`, [SessionMemoryIndexService.remember](src/main/java/org/elasticsearch/xpack/contextengine/memory/SessionMemoryIndexService.java#L75) sends the prompt and the content through `UnifiedCompletionAction` as a non-streaming request, replaces `content` with the reply, and then indexes the memory. The stored `content`, the `inputs` embedding, and the remember response all contain the redacted text.
- The prompt is a constant in `SessionMemoryIndexService`. It instructs the model to replace names, email addresses, phone numbers, postal addresses, and government or account identifiers with placeholders such as `<NAME>` and `<EMAIL>`, and to return the rest of the text unchanged.

Each remember with content makes one LLM request, and the output is not deterministic. Content that contains instructions can influence the model; the POC does not guard against this.

## PDFs and images

Nothing in Elasticsearch produces redacted image or PDF bytes. There are three ways to support media:

- PDFs as text: extract the text with the `document_extraction` task type, run it through the same prompt, and store the text in place of the PDF.
- Images as text: ask the `chat_completion` endpoint for the image text or a description, using its `image_url` content type, and store that in place of the image.
- Detect and refuse: ask the `decision` task type, which accepts image input, whether the item contains PII, and reject the remember if it does. The media is kept intact or not stored at all.

The first two drop the media bytes, so the embedding covers text instead of the file. Returning a redacted image or PDF would need a new inference task type that takes media in and returns media out.

## Text extraction

`xpack.context_engine.session_memory.extraction.enabled` defaults to `true`, and `xpack.context_engine.session_memory.extraction_inference_id` defaults to `.jina-reader`, the preconfigured EIS Jina Reader endpoint for the `document_extraction` task type. It accepts PDF, image and HTML inputs, with OCR for scanned pages through the `preset: ocr` task setting. The endpoint is in preview and is authorized per account and region, so a cluster without it should set `enabled` to `false`, or name another `document_extraction` endpoint.

When set, `remember` first sends the memory's PDF, image and HTML media to the endpoint and stores the returned text, one block per item separated by blank lines, as `extracted_content`. The media bytes are kept as they are. The extracted text is:

- redacted together with `content` when redaction is on, so PII inside a scanned document does not survive;
- added to the `inputs` semantic field, so the memory is also found by the words in its documents;
- returned by remember, list and search, so recall can describe a PDF instead of only reporting that one exists.

`extracted_content` cannot be supplied by the caller.

Extraction is not possible in an ingest pipeline for the same reason as LLM redaction: the `inference` processor only sends text, and no processor speaks the `document_extraction` task type. The Tika `attachment` processor would cover embedded PDF text but has no OCR.

## Running it locally

Start Elasticsearch:

```
./gradlew run
```

Remember a memory that contains PII:

```
POST _context_engine/session_memory/_remember
{
  "session_id": "s-1",
  "user_id": "kathleen",
  "content": "Call me at 555-123-4567 or kathleen@example.com, I sit next to Bob Smith."
}
```

The response and the stored document contain the redacted text, such as `Call me at <PHONE> or <EMAIL>, I sit next to <NAME>.` Read the stored memory with:

```
GET _context_engine/session_memory?session_id=s-1
```

To use a different endpoint, or to disable redaction:

```
./gradlew run -Dtests.es.xpack.context_engine.session_memory.redaction_inference_id=my-llm
./gradlew run -Dtests.es.xpack.context_engine.session_memory.redaction.enabled=false
```

To use a different `document_extraction` endpoint, or to disable extraction:

```
./gradlew run -Dtests.es.xpack.context_engine.session_memory.extraction_inference_id=my-extractor
./gradlew run -Dtests.es.xpack.context_engine.session_memory.extraction.enabled=false
```
